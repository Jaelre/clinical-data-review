# Security policy

## Supported version

Security fixes are made on the current `main` branch. No other versions are currently supported.

## Reporting a vulnerability

Do not open a public issue for a suspected vulnerability, sensitive log, credential, or privacy incident. Use GitHub’s **Report a vulnerability** private vulnerability reporting flow on the repository Security tab.

Include reproduction steps and impact, but do not attach real patient data, PII/PHI, credentials, private database files, or identifying logs. Use a minimal synthetic reproduction. You should receive an initial acknowledgement within seven days.

This channel is for software vulnerabilities. Data breaches and clinical incidents must also follow the reporter’s organizational and legal incident-response requirements.
